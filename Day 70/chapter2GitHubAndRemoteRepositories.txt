Here's the complete Git workflow from the Working Directory all the way to GitHub, including the most common 
commands.

                 Git Workflow

 Working Directory
        │
        │  git add
        ▼
  Staging Area (Index)
        │
        │  git commit
        ▼
 Local Repository (.git)
        │
        │  git push
        ▼
      GitHub
1. Working Directory

This is where you edit your files.

Example:

touch app.py

or

code app.py

Check the status:

git status
2. Initialize Git (only once)

If the project is not already a Git repository:

git init
3. Add files to the Staging Area

Add one file:

git add app.py

Add multiple files:

git add file1.py file2.py

Add everything:

git add .

Check status:

git status

You should see:

Changes to be committed
4. Commit to the Local Repository

Create a snapshot:

git commit -m "Add login feature"

View commit history:

git log

Compact history:

git log --oneline
5. Connect your project to GitHub (first time only)

Create a repository on GitHub, then connect it:

git remote add origin https://github.com/username/repository.git

Verify:

git remote -v
6. Push to GitHub

First push:

git push -u origin main

or if your branch is called master:

git push -u origin master

Future pushes:

git push
7. Download changes

Download and merge:

git pull

Download without merging:

git fetch
Complete workflow
git status
git add .
git commit -m "Describe your changes"
git push
If you're starting a brand-new project
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/username/repository.git
git push -u origin main
Useful Git commands
Command	Purpose
git init	Initialize a Git repository
git status	Show the current status
git add .	Stage all changes
git add file.py	Stage a specific file
git commit -m "message"	Create a commit
git log	View commit history
git log --oneline	Compact commit history
git diff	Show unstaged changes
git diff --staged	Show staged changes
git branch	List local branches
git checkout branch-name	Switch branches
git switch branch-name	Modern way to switch branches
git switch -c new-branch	Create and switch to a new branch
git merge branch-name	Merge a branch into the current branch
git remote -v	Show remote repositories
git push	Upload commits to GitHub
git pull	Download and merge remote changes
git fetch	Download remote changes without merging
git clone <repository-url>	Copy a remote repository to your computer
git restore file.py	Discard unstaged changes to a file
git restore --staged file.py	Remove a file from the staging area
git rm file.py	Remove a file and stage the deletion
git mv old.py new.py	Rename or move a file
git reset --soft HEAD~1	Undo the last commit, keep changes staged
git reset --hard HEAD~1	Undo the last commit and discard changes (destructive)

This is the complete workflow you'll use in most software development projects. Once you understand these four 
stages—Working Directory → Staging Area → Local Repository → GitHub—the rest of Git commands build on this 
foundation.
